# Linting — biome in `apps/www`

`@biomejs/biome` is pinned at **1.5.3** and configured by `apps/www/biome.json`. It runs
only in `apps/www` (`bun run lint`), and CI gates it via the `lint` job in
`.github/workflows/checks.yml`. `bun run lint` must exit 0.

Do not upgrade past 1.5.3 as a drive-by — 2.x renames rules, changes the config schema,
and replaces `--apply` with `--write`.

## Three standing configuration decisions

1. **Formatter off** (`formatter.enabled: false`, `organizeImports.enabled: false`).
   Prettier owns formatting repo-wide via the root `.prettierrc` (single quotes, no
   bracket spacing, 2-space indent, width 100). Biome's defaults are tabs/double
   quotes/width 80, so enabling its formatter would flag all ~105 source files purely
   because two formatters disagree — and mirroring `.prettierrc` in biome is not
   byte-identical either. **Biome is a linter only.**
2. **`complexity/useArrowFunction` off.** House style mandates `function ()` over
   `() =>` (global `code-style.md`, `testing.md`); the test suite follows it in ~95
   places. The rule contradicts the documented convention, so it is disabled rather
   than the code being rewritten. Never run `bun run fix` (`--apply`) blindly — it
   would convert every one of those callbacks.
3. **Ignored paths** (`files.ignore`): `dist/**`, `.tanstack/**`,
   `src/routeTree.gen.ts`. Biome 1.5.3 does not read `.gitignore` unless
   `vcs.useIgnoreFile` is set, so without this the error count swings by ~1500
   depending on whether you last ran `vite build`. `routeTree.gen.ts` is generated by
   TanStack Router and must not be hand-edited — it is ignored *by biome only*, it
   stays committed.

`biome.json` (not `.jsonc`) cannot carry `//` comments in 1.5.3 — the rationale lives
here instead.

## Standing suppressions

Every `biome-ignore` must state *why* after the colon. Two rules are suppressed today:

- **`correctness/useExhaustiveDependencies`** ×3 — `daily-summary.tsx`,
  `use-form-validation.ts`, `feed-page.tsx`. Biome 1.5.3 demands member expressions
  (`dates[index + 1]`, `schema[field]`) as literal deps, and misreads destructured
  props as non-reactive "outer scope values". Never edit these dependency arrays to
  appease the linter — doing so introduces stale closures or drops a needed re-run.
- **`security/noDangerouslySetInnerHtml`** ×1 — `__root.tsx`, the pre-hydration theme
  script (`react-components.md` #2). It must run synchronously before React hydrates.

In JSX, a suppression comment must be a `//` comment **inside the opening tag**, on the
line directly above the offending attribute. A `{/* … */}` JSX comment node does not
register and reports `suppressions/unused`.
